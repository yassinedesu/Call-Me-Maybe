Lay out the repository

The subject dictates this structure exactly. The two things people forget: src/ needs an __init__.py so python -m src resolves, and the SDK you copy in is the outer folder (the one that carries its own pyproject.toml).

project treetext
call-me-maybe/
├── pyproject.toml          # your project (numpy, pydantic, llm_sdk)
├── uv.lock                 # generated by uv sync
├── README.md
├── Makefile
├── src/
│   ├── __init__.py
│   └── __main__.py         # entry point for `python -m src`
├── llm_sdk/                # copied whole from the provided package
│   ├── llm_sdk/__init__.py # └─ the Small_LLM_Model class
│   ├── pyproject.toml
│   └── uv.lock
└── data/
    └── input/
        ├── functions_definition.json
        └── function_calling_tests.json
put the pieces in placebash
mkdir -p call-me-maybe/src call-me-maybe/data
cd call-me-maybe
cp -r /path/to/unzipped/llm_sdk ./llm_sdk       # the OUTER folder
cp -r /path/to/unzipped/data/input ./data/input
touch src/__init__.py

Build the environment with uv

The reviewer runs a single command: uv sync. So your root pyproject.toml has to declare everything, including the local SDK. The key line is [tool.uv.sources] — it points llm-sdk at your local folder instead of PyPI, and installing it drags in torch, transformers, and huggingface-hub from the SDK's own manifest.

pyproject.tomltoml
[project]
name = "call-me-maybe"
version = "0.1.0"
requires-python = ">=3.10"
dependencies = [
    "numpy",
    "pydantic",
    "llm-sdk",
]

[tool.uv.sources]
llm-sdk = { path = "llm_sdk", editable = true }

Then let uv resolve and install into a fresh .venv/:

terminalbash
uv sync
First run is slow. uv pulls torch (hundreds of MB). That's a one-time cost — the lockfile makes every later uv sync fast and reproducible, which is exactly what the moulinette relies on.

Download the model on first construction

The SDK ships code, not weights. The first time you build Small_LLM_Model(), it fetches Qwen/Qwen3-0.6B (~1.2 GB) from the HuggingFace Hub and caches it under ~/.cache/huggingface/. Every run after that is offline and instant to load.

There's no separate download command — construction is the download. So the only requirement for Step 2 is: have a network connection the first time you run Step 3.

Smoke-test the engine

Before writing a single line of decoding logic, prove the model breathes. This is the whole point of the setup: one forward pass, in, out. Drop this at the repo root.

smoke_test.pypython
import numpy as np
from llm_sdk import Small_LLM_Model

model = Small_LLM_Model()                     # downloads once, then cached

ids = model.encode("The capital of France is")[0].tolist()  # [0] unwraps batch dim
logits = model.get_logits_from_input_ids(ids)         # ~151936 floats

print("vocab size:", len(logits))
print("next token:", repr(model.decode([int(np.argmax(logits))])))
run it through uvbash
uv run python smoke_test.py
Expected — this is green: a vocab size near 151936 and a next token like ' Paris'. If you see that, the model runs and everything downstream is just logic layered on get_logits_from_input_ids.

Why [0].tolist() matters: encode returns a 2-D tensor (batch × tokens), but get_logits_from_input_ids wants a flat list[int]. The [0] unwraps the batch dimension; .tolist() drops the tensor. Miss it and you'll hand the SDK the wrong shape.

Make python -m src runnable

The grader invokes uv run python -m src --functions_definition … --input … --output …. So src/__main__.py must exist and parse those three flags with the documented defaults. A stub that proves the contract:

src/__main__.pypython
import argparse


def main() -> None:
    p = argparse.ArgumentParser()
    p.add_argument("--functions_definition",
                   default="data/input/functions_definition.json")
    p.add_argument("--input",
                   default="data/input/function_calling_tests.json")
    p.add_argument("--output",
                   default="data/output/function_calling_results.json")
    args = p.parse_args()
    print("args OK:", args)


if __name__ == "__main__":
    main()
terminalbash
uv run python -m src

If that prints your parsed args, the invocation contract is satisfied. From here, main() is where the real project plugs in: load the two JSON files, loop the prompts, run constrained decoding, write the output array.

Before you move on

Five things that bite people

G · 01

encode returns 2-D

A batch × tokens tensor. Always bridge to the SDK with [0].tolist() or you'll pass the wrong shape into get_logits_from_input_ids.

G · 02

No KV-cache is exposed

Each generation step re-runs a full forward pass over the whole sequence — it's O(n²) in tokens. Fine for short function-call JSON; just don't expect it to be instant.

G · 03

CPU is the fallback

No GPU or Apple MPS → it auto-selects cpu + float32. Slower but correct. The 5-minute budget for all prompts stays comfortable at these output lengths.

G · 04

Package shadowing

If some other llm_sdk is installed globally, make sure imports resolve to the provided one. Running everything through uv run keeps the .venv active and correct.

G · 05

Model choice is downstream

Getting logits flowing is "running the model." Which function to call and the masking that enforces it live entirely on top of Step 3 — a separate concern from setup.

Setup ends here

A green smoke test is the starting line, not the finish

Everything above is plumbing: it guarantees the model returns logits and the grader's command runs. None of it is the graded skill. That skill is the constrained decoder — the state machine that, at every token, sets illegal logits to −∞ so the model can only ever emit schema-valid JSON. The function gets chosen by the model's surviving probabilities, never by an if "sum" in prompt heuristic.
